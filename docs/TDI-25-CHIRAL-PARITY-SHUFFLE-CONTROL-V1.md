# TDI-25 chiral parity-shuffle control v1 (slice 34)

Status: Phase-D Development/Validation software control. Contract
`tdi25-chiral-parity-shuffle-control-v1`. No training, no protected/final
access, no confirmatory execution and no scientific claim. No configuration
freeze pin is introduced or changed; holdouts are untouched.

## Population and budget

The control reuses the unchanged matched population
`tdi25-matched-reference-population-v1` (see `TDI-25-MATCHED-REFERENCE-V1.md`)
and the Stage-C preflight budget: every required family (TorsorFavorable,
ChiralFavorable, Mixed, Neutral), seed blocks `0..seed_blocks` (at most 2) and
`cases_per_block` cases (2..16) per block, in that canonical order. Cases are
generated by the v1 protocol only; there is no filtering or retry.

## Reference and control

- **Reference**: the unchanged matched C6 score with
  `MATCHED_CHIRAL_WEIGHTS = (alpha, beta, gamma) = (1, 0, 1)` through the
  upstream TDI-24 contract `tdi24-mirror-coupled-chiral-v1`
  (`chiral_arm_score`). It is reused from the matched primary run and
  re-checked bit for bit against an independent rescoring, together with its
  match bit.
- **Control**: the same weights through the same `chiral_arm_score`, applied
  to `P q` and `P k`, where `P` is one fixed carrier-slot permutation.

## The shuffle

`P` is the TDI-24 slice-34 parity shuffle (`tdi24-parity-shuffle-control-v1`)
consumed unchanged: `parity_shuffle_from_seed` draws a Fisher–Yates
permutation from a SplitMix64 stream and deterministically rejects draws that
keep or swap the parity sectors as blocks (bounded by
`MAX_PARITY_SHUFFLE_DRAWS = 64`, a software termination bound, not a freeze
pin). `validate_parity_shuffle` checks exactly that `P^T M P != ±M` and
`P^T J P != ±J`, so neither the mirror involution nor the complex structure
survives the relabelling.

The seed is **not new seed material**: it is the already-registered TDI-25
seed `(split domain, ChiralFavorable, 0)`, i.e. the mixed seed of the first
ChiralFavorable case of the matched population. One permutation is used per
split.

Both sides use `ParameterReadoutCapacity::reference_c6()`: zero trainable
parameters, identical weights, readout and match tolerance.

## Checked identities and rejections

- **Six values preserved**: the multisets of the six query and the six key
  values are identical bit for bit before and after the shuffle
  (`six_values_drift`).
- **Direct-product multiset preserved**: the six coordinate products
  `q_i k_i` are the same multiset bit for bit (`direct_product_multiset_drift`).
- **Structure destroyed**: block-preserving or block-swapping permutations are
  rejected (`sector_blocks_preserved`), as are permutations that preserve `M`
  or `J` up to sign.
- **Reproducible shuffle**: the stored seed and permutation must be
  regenerated exactly (`seed_drift`, `shuffle_not_reproducible`).
- **Regenerated evidence**: the validator regenerates every case from the
  canonical matched population `(split, family, seed_block, case_id)`, its
  evaluator-owned target and the reproducible shuffle and requires exact
  equality (`case_evidence_drift`).

Validation also rejects contract, population, chiral-contract or upstream
shuffle-contract drift, weight drift on either side, capacity mismatch,
case-count or canonical-order drift, tampered family summaries, and any
protected/final access, training or scientific-claim flag. Protected/final
split labels never generate a case.

## Recorded degeneracies

1. **ChiralFavorable target is the reference score.** As recorded in slice 33,
   the ChiralFavorable common target `s + chi` is exactly the matched C6 score,
   so the reference matches by construction. The control's loss of matches is
   a restatement of that construction, not independent attribution evidence.
2. **Direct channel unchanged up to summation order.** Because the direct
   products are only relabelled, `s` changes at most by floating-point
   summation order; the control effectively replaces `chi` by the parity-odd
   observable of the relabelled pair.
3. **Other families.** Neither side matches the TorsorFavorable, Mixed or
   Neutral targets on the smoke budget; these are software diagnostics only.

## What is recorded

Per case: reference and shuffled scores, both parity-odd observables, the
six-values and direct-product preservation flags and both match bits. Per
family: case count, reference matches, shuffled matches and cases whose
parity-odd observable changed. Interpreting them as attribution evidence is
reserved for the Stage-D attribution audit (slice 40).
