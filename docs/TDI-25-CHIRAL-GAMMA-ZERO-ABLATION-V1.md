# TDI-25 chiral `gamma=0` ablation v1 (slice 33)

Status: Phase-D Development/Validation software ablation. Contract
`tdi25-chiral-gamma-zero-ablation-v1`. No training, no protected/final
access, no confirmatory execution and no scientific claim. No configuration
freeze pin is introduced or changed; holdouts are untouched.

## Population and budget

The ablation reuses the unchanged matched population
`tdi25-matched-reference-population-v1` (see `TDI-25-MATCHED-REFERENCE-V1.md`)
and the Stage-C preflight budget: every required family (TorsorFavorable,
ChiralFavorable, Mixed, Neutral), seed blocks `0..seed_blocks` (at most 2) and
`cases_per_block` cases (2..16) per block, in that canonical order. Cases are
generated by the v1 protocol only; there is no filtering or retry.

## Reference and ablation

- **Reference**: the unchanged matched C6 score with
  `MATCHED_CHIRAL_WEIGHTS = (alpha, beta, gamma) = (1, 0, 1)` through the
  upstream TDI-24 contract `tdi24-mirror-coupled-chiral-v1`
  (`chiral_arm_score`). It is reused from the matched primary run and
  re-checked bit for bit against an independent rescoring, together with its
  match bit.
- **Ablation**: the same weights with only the parity-odd coefficient zeroed,
  `(alpha, beta, 0)`, on the identical six query and six key scalars, through
  the same upstream `chiral_arm_score`.

Both sides use `ParameterReadoutCapacity::reference_c6()`: zero trainable
parameters, identical inputs, readout and match tolerance.

## Checked identities and rejections

Per case the report records both scores, the unweighted parity-odd observable
`chi = q^T J k`, whether the ablation's right/left enantiomorphic scores
coincide, and both match bits against the evaluator-owned common target.

- **Exact parity-odd residual**: `reference == ablated + gamma * chi` exactly;
  both sides share the identical `alpha*s + beta*m` accumulation, so no
  tolerance is needed (`parity_odd_residual`).
- **Closed enantiomorphic split**: with `gamma = 0` the right and left
  enantiomorphic scores coincide bit for bit and equal the ablated score
  (`enantiomorphic_split`).
- **Inactive channel**: a case with `chi == 0` must have identical scores and
  match bits on both sides (`inactive_channel_drift`).

Validation also rejects contract, population or chiral-contract drift,
reference or ablated weight drift, capacity mismatch, case-count or
canonical-order drift, tampered family summaries, and any protected/final
access, training or scientific-claim flag. Protected/final split labels never
generate a case.

## Recorded degeneracies

1. **ChiralFavorable target is the reference score.** The ChiralFavorable
   common target is `s + chi`, which is exactly the matched C6 score with
   `(1, 0, 1)`. The reference therefore matches 16/16 by construction on the
   smoke budget, and the ablation can only match where `chi = 0`; on the smoke
   budget every ChiralFavorable case has `chi != 0`, so the ablation matches
   0/16 on Development and on Validation. This is a restatement of the target
   construction, not independent attribution evidence.
2. **`beta = 0` in the reference.** As in TDI-24 slice 32, the matched C6
   weights already carry `beta = 0`, so the ablated score is the direct
   channel `s` alone.
3. **Other families.** On the smoke budget neither side matches the
   TorsorFavorable, Mixed or Neutral targets except two Validation
   TorsorFavorable cases on the ablated side; these are software diagnostics
   only.

## What is recorded

Per case: reference and ablated scores, parity-odd observable, closed-split
flag and both match bits. Per family: case count, reference matches, ablated
matches and cases with an active (non-zero) parity-odd observable.
Interpreting them as attribution evidence is reserved for the Stage-D
attribution audit (slice 40).
