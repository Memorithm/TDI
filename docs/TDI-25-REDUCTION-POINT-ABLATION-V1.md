# TDI-25 torsor reduction-point ablation v1 (slice 31)

Status: Phase-D Development/Validation software ablation. Contract
`tdi25-torsor-reduction-point-ablation-v1`. No training, no protected/final
access, no confirmatory execution and no scientific claim. No configuration
freeze pin is introduced or changed; holdouts are untouched.

## Population and budget

The ablation reuses the unchanged matched population
`tdi25-matched-reference-population-v1` (see `TDI-25-MATCHED-REFERENCE-V1.md`)
and the Stage-C preflight budget: every required family (TorsorFavorable,
ChiralFavorable, Mixed, Neutral), seed blocks `0..seed_blocks` (at most 2) and
`cases_per_block` cases (2..16) per block, in that canonical order. Cases are
generated by the v1 protocol only; there is no filtering or retry.

## Reference and ablation

- **Reference**: the unchanged matched T6 score, the TDI-22 factorized pairing
  `(v + Q x omega).R + omega.(M(P) + P x R)`. It is reused from the matched
  primary run and re-checked bit for bit, together with its match bit.
- **Ablation**: `v.R + omega.M(P)`. Same six query, six key and six geometry
  scalars, same zero trainable parameters, updates, readout and tolerance
  (`ParameterReadoutCapacity::reference_t6()` on both sides). Only the
  Varignon transport of the moment from P to Q is removed.

Removed term: `omega.((P - Q) x R)`, using the TDI-22 convention
`M(Q) = M(P) + (P - Q) x R`.

## Monitored identity and rejections

Each case must satisfy `reference = ablated + transport_term` within the
shared v1 relative tolerance `1e-12 * (1 + max(|lhs|, |rhs|))`
(`transport_residual` otherwise). A case whose stored reduction point equals
the query point must carry an exactly zero transport term
(`coincident_point_transport`). Chiral and Neutral populations set
`P = Q = 0` by protocol, so the ablation is an exact no-op there; this is a
built-in negative control.

Validation also rejects contract or population drift, capacity mismatch,
case-count or canonical-order drift, tampered family summaries, and any
protected/final access, training or scientific-claim flag. Protected/final
split labels never generate a case.

## What is recorded

Per case: reference and ablated scores, the transport term, whether the
reduction points coincide, and both match bits against the evaluator-owned
common target. Per family: case count, reference matches, ablated matches and
transport-active cases. These are software diagnostics on a favorable-by-
construction target; interpreting them as attribution evidence is reserved
for the Stage-D attribution audit (slice 40).
