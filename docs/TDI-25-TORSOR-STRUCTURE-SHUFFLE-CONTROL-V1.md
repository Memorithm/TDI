# TDI-25 torsor structure-shuffle control v1 (slice 35)

Status: Phase-D Development/Validation software control. Contract
`tdi25-torsor-structure-shuffle-control-v1`. No training, no protected/final
access, no confirmatory execution and no scientific claim. No configuration
freeze pin is introduced or changed; holdouts are untouched.

## Population and budget

The control reuses the unchanged matched population
`tdi25-matched-reference-population-v1` and the Stage-C preflight budget:
every required family (TorsorFavorable, ChiralFavorable, Mixed, Neutral), seed
blocks `0..seed_blocks` (at most 2) and `cases_per_block` cases (2..16) per
block, in that canonical order. Cases are generated by the v1 protocol only;
there is no filtering or retry.

## Reference and control

- **Reference**: the unchanged matched T6 factorized score
  `(v + Q x omega).R + omega.C`, `C = M(P) + P x R`, through the upstream TDI-22
  contract (`torsor_arm_score`). It is reused from the matched primary run and
  re-checked bit for bit against an independent rescoring, with its match bit.
- **Control**: the same `torsor_arm_score` applied to the relabelled twist
  `P (v | omega)` and torsor `P (R | M(P))`, with the reduction point `P` and the
  query point `Q` unchanged, where `P` is one fixed carrier-slot permutation.

## The shuffle

`P` is the TDI-24 slice-34 shuffle (`tdi24-parity-shuffle-control-v1`) consumed
unchanged: `parity_shuffle_from_seed` draws a Fisher–Yates permutation from a
SplitMix64 stream and deterministically rejects draws that keep or swap the two
three-slot blocks (here: linear/angular for the twist, resultant/moment for the
torsor), bounded by `MAX_PARITY_SHUFFLE_DRAWS = 64`, a software termination
bound, not a freeze pin. Every accepted `P` therefore moves at least one
resultant slot into a moment slot and vice versa, so the Varignon convention
`M(Q) = M(P) + (P - Q) x R` no longer acts on the quantities it was written for.

The seed is **not new seed material**: it is the already-registered TDI-25 seed
`(split domain, TorsorFavorable, 0)`, i.e. the mixed seed of the first
TorsorFavorable case of the matched population. One permutation is used per
split. Both sides use `ParameterReadoutCapacity::reference_t6()`.

## Checked identities and rejections

- **Six values preserved**: the six query and six key value multisets are
  identical bit for bit (`six_values_drift`).
- **Untransported products preserved**: the six coordinate products `q_i k_i`
  of the untransported pairing `v.R + omega.M(P)` are the same multiset bit for
  bit (`untransported_product_multiset_drift`). Only the transport term and its
  cross-block coupling can change.
- **Structure destroyed**: block-preserving or block-swapping permutations are
  rejected (`sector_blocks_preserved`), as are permutations that preserve the
  block selector or the block exchange up to sign.
- **Reproducible shuffle**: the stored seed and permutation must be regenerated
  exactly (`seed_drift`, `shuffle_not_reproducible`).
- **Regenerated evidence**: every case is regenerated from the canonical
  matched population, its evaluator-owned target and the reproducible shuffle
  and must be equal (`case_evidence_drift`).

Validation also rejects contract, population, torsor-contract or upstream
shuffle-contract drift, capacity mismatch, case-count or canonical-order drift,
tampered family summaries, and any protected/final access, training or
scientific-claim flag. Protected/final split labels never generate a case.

## Recorded degeneracies

1. **TorsorFavorable target is the reference score**, as for the chiral
   counterpart: the reference matches by construction, so the control's loss
   of matches restates that construction and is not independent attribution
   evidence.
2. **Zero transport cases.** Cases whose reduction point equals the query
   point, or whose relabelled angular/resultant parts vanish, can keep the same
   transport term; the unchanged counts are recorded, not filtered.
3. **Other families.** Neither side matches the ChiralFavorable, Mixed or
   Neutral targets on the smoke budget; these are software diagnostics only.

## What is recorded

Per case: reference and shuffled scores, both transport terms, the six-values
and untransported-product preservation flags and both match bits. Per family:
case count, reference matches, shuffled matches and cases whose transport term
changed. Interpreting them as attribution evidence is reserved for the Stage-D
attribution audit (slice 40).
